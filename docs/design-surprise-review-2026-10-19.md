## 1. 기준선: 무엇이 안 맞았나

10-18 실행의 Design 단계는 design-library의 브랜드 DESIGN.md 86개에서 후보를 무작위로 뽑는다. 프롬프트가 "분야가 다른 후보"를 쓰라고 정해 두어서, 전시 추천 앱에 자동차 브랜드(bmw-m)의 레이싱 타이밍 타워가 붙었다. 종료일 순 순위표에 3색 띠를 추천 점수 범례로 쓴 화면이다.

| 안 | 원천 | 내용 |
| --- | --- | --- |
| A 기준안 | cal | 흰 바탕 캘린더 카드 |
| B 의외안 (선택됨) | bmw-m | 종료일 순 순위표, 3색 띠 |
| C 의외안 | opencode.ai + nerdwallet | 판정 로그와 비교표 |

## 2. 의외성의 뜻을 다시 정하다

보기 넷 가운데 사용자는 2번과 3번을 함께 골랐다.

| 보기 | 뜻 | 선택 |
| --- | --- | --- |
| 1 | 어울리되 한 군데만 새로움 | - |
| 2 | 같은 분야 안의 낯선 표현(도록, 포스터, 리플릿, 티켓 등) | 선택 |
| 3 | 오늘 볼 전시를 고르는 방식의 의외성 | 선택 |
| 4 | 작품이 주인공인 갤러리형 | - |

이로써 10-18의 "의외성 우선" 결정이 좁혀졌다. 다른 분야의 디자인 언어를 옮기는 것이 아니라, 전시 세계 안에서 낯선 것이다.

## 3. 1차 시안 실패와 참조 다시 가져오기

1차 시안 셋은 전시 세계의 형식(리플릿, 입장권, 벽면 캡션)을 빌렸지만, 사용자는 "디자인이 전혀 안 바뀐 느낌"이라고 했다. 브랜드 라이브러리를 빼고 참조 없이 만들었기 때문에, 결과가 모두 비슷한 무채색으로 수렴했다.

그래서 참조 수집부터 다시 했다. 미술관 사이트 12곳의 홈 HTML과 CSS에서 색과 글꼴이 쓰인 빈도를 세고 1280px 화면을 캡처한 뒤, 서로 가장 다른 셋을 골랐다.

| 디자인 | 참조 | 실측 색 | 가져온 요소 |
| --- | --- | --- | --- |
| A | New Museum | #000 #beff00 #00b2ff | 검정 바탕, 애시드 라임 거대 글자, 와이드 그로테스크 |
| B | Barbican | #d14900 #333 #1a1a1a | 주황 전면 헤더, 흰 굵은 산세리프, 6px 둥근 버튼 |
| C | Stedelijk | #0a0a0a #ebeae8 #22ff06 #ffd511 | 거대한 얇은 글자, 5px 검정 괘선, 형광 초록 선택, 기울어진 노랑 스티커 |

나머지 9곳은 채택한 셋과 겹치거나(Whitney, Palais de Tokyo), 흑백 위주이거나(MoMA, Kunsthalle Basel), 추출에 실패해 보류했다. 글꼴은 대체품(Archivo, Black Han Sans, Outfit, Pretendard, Helvetica Neue)이다.

## 4. 디자인과 고르는 방식을 떼어 내다

2차 시안에서 사용자는 C를 골랐다. 이어서 "시안과 고르는 방식을 매칭한 이유"를 물었고, 답은 "강한 이유는 없다"였다. 고르는 방식 셋이 1차 때 먼저 정해져 있었고, 참조는 나중에 그 자리에 하나씩 넣은 것이었다. 이 상태로는 C를 좋게 본 이유가 디자인인지 질문형 고르기인지 나눌 수 없었다.

그래서 둘을 떼어 3 × 3으로 만들었다. 고르는 규칙은 `logic.js` 하나에 두고, 디자인은 CSS 세 벌로 바꿨다.

| 방식 | 사용자가 하는 일 | 규칙 | 10-18 결과 | 바꿀 곳 |
| --- | --- | --- | --- | --- |
| 1 추천 Top 3 | 없음 | 기준선 F4 점수 상위 3개, 갤러리당 1개 | 박서보, Moon Mind, Míope | Design만 |
| 2 시간 동선 | 2시간/반나절/하루 | 오늘 닫는 전시가 많은 동네부터 시간 안에 채움 | 반나절: 삼청·북촌 5곳, 약 3.5시간 | Design + Plan F4 + 데이터 |
| 3 질문형 | 오늘 아니면 못 봄 / 이번 주 / 급하지 않음 / 전부 | 점수 없이 남은 날로 나눔 | 오늘: 4건 | Design + Plan F4 |

| 디자인 \ 방식 | 1 추천 Top 3 | 2 시간 동선 | 3 질문형 |
| --- | --- | --- | --- |
| A New Museum | A1 | A2 | A3 |
| B Barbican | B1 | B2 | B3 |
| C Stedelijk | C1 | C2 | C3 |

9개 모두 360px과 1280px에서 가로 넘침이 없고, 버튼 동작을 눌러 확인했다. 2번의 동네와 관람 시간은 확인하지 않은 시안용 가정이다.

## 5. 결정된 디자인은 어디로 들어가나

"결정되면 DESIGN.md를 새로 쓰나"라는 질문에 코드를 확인하고 세 경우로 나눠 답했다.

| 정하는 것 | 들어가는 곳 | 따라오는 것 |
| --- | --- | --- |
| 디자인만 | DESIGN.md를 쓰고 `--design <경로>`로 지정(`cli.py:37`) | 지정한 파일은 Design critic을 거치지 않음(`pipeline.py:361-367`) |
| 고르는 방식까지 | Plan의 spec F4 | spec을 고정해 넣는 옵션은 미확인 |
| 파이프라인이 스스로 이런 디자인을 내게 | design-library와 Design 프롬프트 수정 | mvpgen 자체를 고치는 일 |

## 6. 아키텍처에 반영할 발견

| 발견 | 근거 | 영향받는 곳 |
| --- | --- | --- |
| "분야가 다른 후보" 규칙이 어울리지 않는 디자인을 만든다 | 기준선 레이싱 화면, 사용자 판단 | `DESIGN_SYSTEM` 프롬프트 |
| design-library에 분야에 맞는 원천이 없다 | 86개 모두 일반 브랜드, 전시 기관 0개 | design-library, 후보 추출 규칙 |
| 참조 없이 만든 디자인은 무난하게 수렴한다 | 1차 시안 실패, 실측 참조를 쓴 2차는 달라짐 | 참조 수집 단계 |
| 디자인과 고르는 방식이 다른 단계에 있다 | 고르는 방식은 spec F4라 Design 단계가 바꿀 수 없다 | Plan과 Design의 경계 |
| 디자인과 구조를 한 시안에 묶으면 평가가 섞인다 | C 선호 이유를 나눌 수 없었다 | concepts.json의 시안 구성 |
| 지정한 DESIGN.md는 critic을 건너뛴다 | `pipeline.py` `design()`의 `provided` 분기 | Design 검사 경로 |
| 기준선 F4의 갤러리당 1개 규칙이 오늘 닫는 전시를 뺀다 | 「Pictos and Pitwall」(국제갤러리 K2, 10-18 종료) 누락 | Plan의 F4 검증 |

## 7. 정리와 병합

ARCHIVE에 결정 5행과 새 절을 적고 커밋했다(`0985d22`). 사용자가 참조 사이트 캡처는 빼자고 해서, push 전 커밋을 고쳐 캡처 3장을 이력에서 지우고 비교 페이지에는 사이트 링크만 남겼다(`db3f40e`). PR #7은 `docs/` 안의 파일 18개만 더했고 mvpgen 코드는 바꾸지 않았다. 병합은 사용자가 직접 했다(`01ca3ec`).
